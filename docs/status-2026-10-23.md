# FindMyWalk build status — 23 October 2026

Branch: `build/platform-20261023` in `lozknowles/FindMyWalk`. Development and testing took place on hpubuntu in `/fast/work/findmywalk-platform`; no public deployment or DNS change was made. The existing holding page on `main` remains live.

## Verified in this build

- Next.js application builds with TypeScript and a responsive, photographic homepage and MapLibre route editor.
- Local PostGIS schema and signed browser-owner session support saved drafts, optimistic revisions, public and unlisted publication snapshots, and private route access checks.
- A local Valhalla Nottinghamshire graph returned a real pedestrian route near Collingham. The editor supports waypoint placement, dragging, ordering, reversing, circular routes, manual geometry, and GPX import/export.
- Atomic local OSM import loaded 18,215 POIs and transport features from the Nottinghamshire Geofabrik extract, with explicit coverage checks. Local HTTP queries returned Collingham places and stops; Paris returned `OUTSIDE_COVERAGE`.
- Browser walkthrough at desktop and 390×844 mobile widths: map loaded, waypoints added, reversed and looped, route saved, published, public page opened, GPX downloaded, parsed and reimported; saved walk reopened and private route blocked in a second browser. No page errors or mobile horizontal overflow. This walkthrough used manual geometry; the routing API was checked separately.
- AR browser walkthrough on the rebuilt production server: local OSM discovery, feature details, destination handoff, camera-denied fallback, 390 px layout and no page errors. It uses manual coordinates, a denied-camera fixture, and a simulated GPS fix that successfully requests a real Valhalla walking route. It also adds a destination to an existing saved walk. These fixtures do not establish physical alignment.
- 37 unit tests pass, including owner authority, revision conflicts, snapshots, route validation, GPX, discovery coverage and deterministic AR projection/sensor fixtures, a short-route persistence contract and Google adapter request fixtures. TypeScript, optimized build and both browser smoke scripts pass.

## Implemented with limitations

- Anonymous browser-bound editing is a first vertical slice; it is not a registered account system. Deleting cookies loses edit authority.
- Open-data POI and stop discovery is limited to the imported Nottinghamshire coverage and named shops, historic landmarks, peaks and a bounded set of facilities. Open-data results do not establish current hours, legal access, timetables or live services.
- Geocoding uses a public Photon development endpoint. Production needs a dedicated permitted provider and rate limits.
- Google Places (New) has a server-side adapter with bounded queries and minimal field masks. It is not connected to the MapLibre UI; a compliant Google Maps presentation, billing and genuine credential-backed acceptance remain to be implemented.
- AR Explorer currently positions labels by horizontal compass bearing and an assumed 65° camera field of view, with fixed vertical label lanes. Pitch/roll, camera calibration, elevation, line of sight, occlusion and visual identity matching are absent. It is an approximate browser experience. The camera frames remain local, geographic candidates come from the same open-data discovery API, and tap-to-route enters the existing planner. Browser orientation/location alignment depends on hardware, secure context, permissions and calibration. Desktop fixtures do not prove real-world alignment.
- Routing coverage is Nottinghamshire only. Unavailable routing must be shown as unavailable; manual straight lines are labelled as manual geometry, not safe pedestrian directions.

## Incomplete or blocked from the original mission

- No secure registration/login, verification, recovery, Google sign-in, profile, deletion/export or passkey path yet.
- No nationwide/international POI and routing coverage, licensed terrain/elevation/line-of-sight, visual recognition, or business opening information in AR. Pitch-aware projection, calibration, junction arrows and return-to-route navigation are not implemented.
- No full place-category filters, route-corridor search, pedestrian detour panel, or opening-hours/details UI.
- No timetable/live transport, Walk by Train or Bus mode, or station-to-station suggestions.
- No route discovery index/cards/filters, featured community walks, profiles, favourites, collections, reporting/moderation or contributor attribution workflow.
- No elevation/difficulty/accessibility assessment, route photographs, printable guide, social Open Graph, undo/redo, multiple map styles, or GeoJSON export.
- A PWA manifest is present, but installation and offline behavior have not been tested. No route-following progress/off-route detection or offline map qualification.
- A scoped non-root Docker image builds and excludes local secrets, but there is no production hosting, TLS, DNS, monitoring/alerting or restore rehearsal. Spark reachability and long-term deployment target were not verified.
- No live Google API or physical-device AR acceptance: credentials and suitable device/browser evidence were not available in this build.

These are explicit acceptance gaps, not completed features. Public release needs separate approval and qualification, including provider licensing, privacy, moderation, secure accounts and expanded coverage.
